# the Axis · физическая лаборатория

Испытательный стенд для физики конструкций. Каждая формула, прежде чем
попасть в мод `axis_contraption`, разрабатывается, проверяется и настраивается
здесь — отдельно от движка, без сборки, без сервера, за десять секунд.

Лаборатория не зависит ни от Luanti, ни от внешних библиотек. Нужен только
интерпретатор Lua.

```
./run.sh                    прогон всех экспериментов, сводка
./run.sh --full             полный вывод каждого эксперимента
./run.sh --only 04          один эксперимент
./run.sh --svg --csv        записать графики и данные в out/
./run.sh --list             перечень экспериментов
./run.sh --constants        таблица констант с обоснованием каждой
./run.sh --references       библиография
```

Код возврата 0 — все результаты сошлись с аналитическими эталонами;
1 — есть расхождения.

Отдельный эксперимент запускается сам по себе, с переопределением любых
параметров:

```
luajit experiments/04_air_resistance.lua
luajit experiments/04_air_resistance.lua mass=2500 cd=0.7 area=16 dt=0.0005
luajit experiments/06_lift.lua span=6 fuselage=11 --svg
```

## Правила проекта

Эти правила — не пожелания, они закреплены в коде.

1. **Формула без источника не попадает в лабораторию.** Все ссылки собраны в
   `lab/references.lua` с URL и дословной цитатой, где она есть. Там, где
   источник даёт только качественное описание, вывод расписан в комментарии
   рядом с реализацией и помечен как вывод.

2. **Размерности проверяются исполняемо, а не в комментарии.** В `lab/units.lua`
   живёт алгебра размерностей СИ: величины складываются только совместимые,
   умножение складывает степени. Формулы прогоняются через неё в
   `dimension_selftest()`, и неверно собранное выражение падает с ошибкой.

3. **У эксперимента должен быть ответ, известный не из этого же кода.**
   Замкнутое решение, закон сохранения или порядок сходимости. Сравнение
   симуляции с самой собой не доказывает ничего.

4. **У каждого допуска обязано быть обоснование.** `check.lua` физически не
   даст записать проверку без объяснения, откуда взят порог. Подогнать
   допуск, «пока не зазеленеет», запрещено: расхождение — повод искать
   причину.

5. **Магических чисел нет.** Любое число либо физическая константа с
   источником, либо параметр настройки с пометкой `tuning = true` и
   объяснением, что он означает и почему выбран именно таким. Все они собраны
   в `lab/constants.lua`.

6. **Упрощения проговариваются.** У каждого эксперимента есть раздел
   «Упрощения и что из-за них теряется» — что отброшено, почему и какой
   физический эффект при этом пропадает.

## Проверки соответствия

Эксперименты отвечают на вопрос «верна ли модель». Проверки соответствия в
`parity/` отвечают на другой: «то ли самое стоит в игре». Они загружают
НАСТОЯЩИЕ файлы мода `axis_contraption` и сверяют их с эталонами лаборатории.

```
./run.sh --only П1 --full           сверка формулы сглаживания
./run.sh --only П2 --full           прогон настоящего control() поведений
./run.sh --only П3 --full           инерция вращения и угловое движение
./run.sh --only П4 --full           сопротивление и потолок скорости
./run.sh --only П5 --full           подъёмная сила, сваливание, планирование
./run.sh --only П6 --full           разворот через крен, элероны
./run.sh --only П7 --full           шкала масс и бюджет обшивки
./run.sh --only П8 --full           наведение при строительстве
AXIS_MOD_PATH=/путь/к/моду ./run.sh если мод лежит не рядом
```

Проверка П2 сильнее П1: она не сверяет формулу, а ЗАПУСКАЕТ функцию
`control()` из `behaviours/*.lua` покадрово с разной частотой и сравнивает
результат с замкнутым решением. Считается тот же код и теми же аргументами,
что и на сервере.

П3 идёт дальше: она строит конструкцию настоящим `contraption.refresh`,
сверяет её тензор инерции с `lab/rigid.lua`, прогоняет уравнения Эйлера на
законы сохранения и выполняет `air.control` покадрово. Числа модели она не
хранит у себя, а вычитывает из исходника мода — разойдись они, проверка
сверяла бы модель с устаревшими значениями и молчала.

Если мода рядом нет, проверка честно падает с пояснением, а не делает вид,
что всё в порядке.

Внедрение идёт по одному узлу за итерацию. Поэтому каждая проверка
соответствия знает свою ОБЛАСТЬ ВНЕДРЕНИЯ: в переведённых файлах старой
формулы быть не должно (иначе это откат), а непереведённые печатаются
поимённо как очередь работ. Остаток не скрывается никогда.

| Итерация | Узел | Область | Состояние |
|----------|------|---------|-----------|
| 1 | Сглаживание, не зависящее от кадров | `api/smoothing.lua`, `behaviours/air.lua` | внедрено |
| 2 | То же для наземного и инертного поведений | `behaviours/ground.lua`, `behaviours/inert.lua` | внедрено |
| 3 | Момент инерции вместо сглаживания наклона | `api/inertia.lua`, `api/structure.lua`, `behaviours/air.lua` | внедрено |
| 4 | Потолок скорости из тяги и сопротивления | `api/drag.lua`, `behaviours/air.lua` | внедрено |
| 5 | Подъёмная сила по уравнению NASA | `api/lift.lua`, `behaviours/air.lua`, `parts/*.lua` | внедрено |
| 6 | Разворот через крен, а не поворотом курса | `behaviours/air.lua` | внедрено |
| 7 | Калибровка масс блоков | `api/mass.lua`, `parts/*.lua`, `lab/constants.lua` | внедрено |

## Что лаборатория уже нашла

Стенд собирался не ради отчёта, и первые же прогоны дали конкретные
результаты.

**1. Функция `approach()` в `behaviours/air.lua` зависит от частоты кадров.**
Она написана как `current + (target - current) * min(rate*dt, 1)`. Измеренный
разброс результата в диапазоне от 10 до 240 кадров в секунду — 1.6·10⁻³ по
шкале, где полный ход равен единице. Хуже другое: при `rate*dt >= 1`
ограничение обращает множитель в единицу, и наклон машины скачком встаёт в
конечное положение — на просевшем кадре это рывок. Правильная форма
`current + (target - current) * (1 - exp(-rate*dt))` даёт разброс 1.1·10⁻¹⁶,
то есть машинный ноль. Эксперимент 18.

**2. Утверждение о схеме Верле в моей собственной документации оказалось
неверным.** В `lab/integrate.lua` было написано, что при силе, зависящей от
скорости, схема опускается до первого порядка. Измерение показало ровно 2.00.
Причина: ошибка предсказанной скорости сама порядка dt², а входит она в
слагаемое, уже умноженное на dt/2. Комментарий исправлен по результату
измерения. Эксперимент 16.

**3. Воксельная машина при честной калибровке масс летать не может.** При
плотности блока, соответствующей сухой сосне, машина из 28 блоков весит 4667 кг
при площади крыла 6 м². Нагрузка на крыло — 778 кг/м² против 50…100 у лёгкого
самолёта; сваливание наступает на 373 км/ч. Это не ошибка расчёта, а
следствие того, что блок метровый, а крыло из него — один квадратный метр.
Решение геймплейное: либо блоки в игре заметно легче реальных, либо крыло
считается большей площадью. Принимать его надо осознанно. Эксперимент 06.
*Разрешено итерацией 5 — см. находку 3а.*

**3а. Не летала ни одна постройка, и дело было не только в массе.** Перед
итерацией 5 честная аэродинамика дала запас V_max/V_сваливания = 0.67…0.90 для
всех испытанных конструкций, причём добавление двигателей упиралось в 0.90:
двигатель сам тяжёл и растит мидель. Разбор показал две ошибки счёта, а не
две недостающие настройки. Первая: Cd = 1.05 применялся ко всей машине, то
есть длинный фюзеляж считался плоской стеной той же площади; у тела с
удлинением 7:1 сопротивление в семь раз меньше. Вторая: каркас весил как
кубометр сплошного дерева, тогда как авиационный набор с обшивкой даёт
50…100 кг/м³. После обеих поправок запас стал 1.42…1.47, и машины полетели.
Проверки П4 и П5.

**4. `MAX_SPEED` не может быть независимой константой.** Потолок скорости
выводится из тяги и сопротивления: V_max = √(2T/(Cd·ρ·A)), и растёт он как
корень из тяги, а не линейно. Две независимые ручки на одну величину дают
машину, которая либо не разгоняется, либо упирается в невидимую стену.
Эксперимент 05. *Исправлено итерацией 4.*

**4а. Плотность воздуха в моде расходится сама с собой втрое десятков раз.**
Сопротивление после итерации 4 считается при ρ = 0.182 игровой массы на м³
(30 кг/м³), а из подъёмной силы того же мода следует ρ = 2.61 (435 кг/м³) —
разница в 14.3 раза. Обе величины отстоят от настоящей атмосферы в 25 и 355
раз соответственно. Считай мод сопротивление по «подъёмной» плотности, потолок
машины упал бы с 14 до 3.7 м/с — медленнее шага. Свести три числа в одно
можно только вместе с калибровкой масс. Проверка П4, итерации 5 и 7.

**5. У мода нет момента инерции.** Масса есть, момента инерции нет, поэтому
вращение задаётся сглаживанием `TILT_SMOOTHING`, а не моментом силы. Между тем
для машины из 9 блоков I_yy/I_xx ≈ 12: по тангажу она в двенадцать раз
инертнее, чем по крену, и это должно быть видно в управлении. Эксперимент 11.
*Исправлено итерацией 3.*

**5а. Честное аэродинамическое демпфирование несовместимо с игровой подъёмной
силой.** При внедрении итерации 3 выяснилось: если брать демпфирование по
теории полос с настоящей плотностью воздуха, а момент — от подъёмной силы,
которую даёт мод, равновесный угол тангажа выходит в тысячи градусов. Причина
арифметическая: крыло мода создаёт на одно крыло 137 игровых единиц силы, что
при калибровке 500/3 кг равно 23 кН с квадратного метра при 8 м/с, тогда как
честная аэродинамика даёт там же около 39 Н — разница почти в 600 раз. Момент
получается гигантским, а демпфирование ничтожным. Выход, применённый в
итерации 3: наклон подъёмной силы по углу атаки выводится из констант, которые
в моде уже стоят (LIFT_PER_WING — полная сила крыла, а полная сила достигается
на срывном угле), и тогда момент, жёсткость и демпфирование оказываются в
одной шкале. Проверка П3.

**6. Демпфирование по рысканью у воксельной машины крайне слабое.** При киле
1.5 м² на плече 4 м коэффициент затухания ζ = 0.047 против 0.1…0.3 у
самолётов: колебание гасится больше ста секунд. Демпфирование квадратично по
плечу киля, так что отодвинуть его вдвое вчетверо эффективнее, чем удвоить
площадь. Эксперимент 09.

**7. Собственный вес не создаёт момента — подтверждено.** Момент r × F при
r = 0 строго нулевой, потому что вес приложен ровно в центре масс. Это
подтверждает исправление, внесённое в `behaviours/air.lua` ранее: кренит
только несимметрия внешних сил. Эксперимент 07.

## Как добавить эксперимент

```lua
package.path = ((arg and arg[0] or ""):gsub("[^/\\]*$", "") .. "../?.lua;")
	.. package.path

local experiment = require("lab.experiment")
local check = require("lab.check")

return experiment.define {
	id = "21",
	name = "my_topic",
	title = "Название",

	question = [[Какой вопрос решается и зачем он нужен моду.]],
	model = [[Формулы, единицы, вывод, ссылки на источники.]],
	simplifications = [[Что отброшено и какой эффект из-за этого теряется.]],
	references = { R.some_source },

	params = {
		mass = { value = 1000, note = "масса, кг" },
	},

	run = function(P, ctx)
		local suite = check.new("название")

		suite:close("что проверяем", измерено, эталон, допуск,
			"откуда взят допуск")

		return suite
	end,
}
```

Затем добавить путь в список `FILES` в `run.lua`. Порядок там задан явно —
от простого к сложному, и определять его не должна сортировка имён файлов.

## Почему лаборатория лежит здесь, а не в `mods/`

Две причины. Движок после доработки автоматически подхватывает всё из
каталога `mods/`, и папка без `init.lua` там сломала бы загрузку. Кроме того,
`mods/` целиком исключён из репозитория, а лабораторию надо хранить в
истории вместе с остальным кодом.
